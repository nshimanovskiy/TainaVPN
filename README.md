# Tainavpn

Приложение для **Windows, Linux и Android**, которое отправляет весь трафик устройства в прокси (SOCKS5 или HTTP).
Ядро — [sing-box](https://github.com/SagerNet/sing-box) 1.14 (встроен как библиотека).
Прокси можно получить с сервера одной кнопкой или вставить свой.

```
┌──────────── устройство ────────────┐                 ┌──── прокси из папки ────┐
│ приложения → TUN → sing-box ─────── user:pass@host:port ──────▶ │ (купленные прокси) → интернет │
│                 (Tainavpn)          │                 └─────────────────────────┘
│   UI ── HTTPS /sub/<ключ> ──┐       │
└─────────────────────────────┼───────┘
                              ▼
               VPS: nginx → tainavpn-server :8090  (только выдаёт настройки,
                     читает папку proxies/           трафик пользователей через VPS не идёт)
```

## Состав репозитория

| Папка | Что внутри |
|---|---|
| `server/` | `tainavpn-server`: читает прокси из папки, раздаёт их приложениям, проверяет их работоспособность; админ‑панель |
| `ui/` | общий интерфейс (HTML/JS) — один и тот же на десктопе и Android; здесь же генерируется конфиг sing-box |
| `core/` | обёртка над sing-box (запуск/остановка, логи) |
| `desktop/` | десктоп‑приложение на Wails (Windows/Linux) |
| `mobile/` | Go‑библиотека для Android (собирается `gomobile bind` в `.aar`), отдаёт sing-box TUN от VpnService |
| `android/` | Android‑приложение (Kotlin, VpnService + WebView с общим UI) |
| `deploy/` | Dockerfile, docker-compose, пример `.env`, пример списка прокси, конфиг nginx |

## Откуда берутся прокси

На сервере есть папка **`proxies/`** рядом с `docker-compose.yml` (по умолчанию `/home/taina/tainavpn/proxies/`).
В неё кладутся файлы `*.txt`, по одному прокси в строке:

```
user:pass@host:port            # SOCKS5 (по умолчанию)
socks5://user:pass@host:port   # SOCKS5
http://user:pass@host:port     # HTTP-прокси
host:port:user:pass            # SOCKS5, другая запись
# строки с решёткой — комментарии
```

* **Страна** каждого прокси определяется автоматически по его выходному IP (сервер делает запрос через сам прокси и кэширует результат на сутки).
  Задать вручную — кодом страны через пробел: `user:pass@host:port DE`.
* Каждый пользователь получает **по одному прокси каждой страны**, которая есть в папке. В приложении они показываются флагом и названием страны («🇩🇪 Германия», «🇳🇱 Нидерланды»), пользователь выбирает нужную.
* Свои прокси, добавленные вручную, тоже показываются флагом: приложение спрашивает у сервера страну прокси (`POST /api/v1/geo`).
* Изменения в папке подхватываются за 10 секунд, перезапуск не нужен.
* Каждый прокси проверяется каждые 3 минуты (для SOCKS5 — что логин и пароль подходят). Нерабочие никому не выдаются.
* Внутри страны пользователю закрепляется **свой** прокси: сначала свободные, потом наименее загруженные.
  Если его прокси удалили из папки или он перестал работать — при следующем подключении выдаётся другой той же страны.
* IP самого VPS пользователям не выдаётся: приложение подключается напрямую к прокси из папки, VPS только сообщает какой.

## Как пользователь получает прокси — Telegram‑бот

1. Пользователь пишет Telegram‑боту. Бот выдаёт ему **личную ссылку‑подписку** `https://vpn.sdsds.top/sub/<ключ>`
   (один Telegram‑аккаунт — один ключ) и присылает файл приложения для Windows / Android / Ubuntu.
2. В приложении: **+ Добавить → По ссылке** → вставить ссылку. Появятся прокси всех стран, выбирается любая.
   Перед каждым подключением ссылка опрашивается заново.
3. В боте можно **выпустить новую ссылку** — старая сразу перестаёт работать (если ссылка утекла).
4. В админ‑панели (`https://vpn.sdsds.top/adminadminadmin`) видны пользователи (Telegram ID, выданные прокси, последний вход и IP)
   и все прокси из папки. Пользователя можно выключить (бот скажет «доступ отключён»), удалить или выдать ему другие прокси.
   Ключ можно создать и вручную — «Создать ключ».

Получать прокси из самого приложения нельзя — только по ссылке.

### Настройка бота

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и скопируйте токен.
2. На сервере впишите его в `~/tainavpn/.env`: `TVPN_BOT_TOKEN=123456:ABC...`
3. `cd ~/tainavpn && docker compose up -d` — бот запустится в контейнере `tainavpn-bot`.
   Ссылка на бота появится в админке и кнопкой «Открыть Telegram‑бота» в приложении.
4. Ограничить, кому бот выдаёт ссылки: `TVPN_BOT_ALLOWED=123456789,@username` (пусто — всем).
   Незнакомому пользователю бот покажет его Telegram ID, чтобы он мог прислать его вам.

Бот работает через long polling — входящие порты и вебхук не нужны. С сервером он общается по `127.0.0.1`
с общим секретом `TVPN_BOT_SECRET` (создаётся при деплое). Файлы приложений релиз сам кладёт в `~/tainavpn/downloads/`.

Свой прокси добавляется во вкладке «Свой прокси»: строкой `логин:пароль@хост:порт` (или `http://…`, `хост:порт:логин:пароль`) или полями.

## Сервер (VPS)

### Первый запуск через GitHub Actions

Вход под root не нужен: деплой заходит по SSH под обычным пользователем.

1. В **Settings → Secrets and variables → Actions** добавьте секреты:
   `VPS_HOST`, `VPS_PORT` (ваш SSH‑порт), `VPS_USER` (обычный пользователь), `VPS_SSH_KEY` (приватный ключ, публичный — в `~/.ssh/authorized_keys` этого пользователя).
2. Один раз на сервере дайте этому пользователю доступ к Docker: `sudo usermod -aG docker <пользователь>` и перезайдите.
   (Либо sudo без пароля для docker — деплой сам попробует `sudo -n docker`.)
3. **Actions → Deploy server → Run workflow** (в поле укажите домен, по умолчанию `vpn.sdsds.top`).
   Файлы ложатся в `~/tainavpn` пользователя деплоя (другую папку можно задать переменной репозитория `VPS_DIR`).
   При первом деплое создаётся `~/tainavpn/.env` со случайным `TVPN_ADMIN_TOKEN` — посмотреть: `grep ADMIN_TOKEN ~/tainavpn/.env`.
4. Nginx (существующие сайты не трогаются, тут один раз нужен sudo): скопируйте `deploy/nginx-vpn.conf` в `/etc/nginx/sites-available/vpn.sdsds.top`,
   включите (`ln -s … /etc/nginx/sites-enabled/`), `sudo nginx -t && sudo systemctl reload nginx`, затем `sudo certbot --nginx -d vpn.sdsds.top`.
5. Положите прокси в `~/tainavpn/proxies/*.txt`.

Дальше сервер **обновляется сам**: при каждом push в `main`, который меняет серверный код (`server/`, `bot/`, `deploy/`, `go.mod`),
Build сначала прогоняет тесты сервера и только после их успеха запускает деплой. Ручная кнопка **Run workflow** тоже осталась.
Папка `proxies/`, `.env` и `data/` при обновлении не трогаются.

### Переменные `.env`

См. `deploy/.env.example`: имя сервиса, адрес API, токен и путь админки, настройки Telegram‑бота.

### Безопасность

* Трафик пользователей через VPS не идёт, на VPS не открыто никаких портов, кроме уже существующего nginx.
* Пароли прокси не показываются в админ‑панели; приложение получает только тот прокси, который выдан его ключу.
* Если нужно, чтобы и адрес API не указывал на IP VPS, домен `vpn.sdsds.top` можно пропустить через Cloudflare (оранжевое облако) — тогда пользователи видят только адреса Cloudflare.

## Приложения

Готовые файлы — на странице **Releases** репозитория. В каждом релизе три файла:

| Система | Файл | Установка |
|---|---|---|
| Windows 10/11 (64‑bit) | `Tainavpn-<версия>-windows-x64.exe` | установка не нужна, просто запустить; попросит права администратора (нужно для режима «весь трафик») |
| Android 7.0+ | `Tainavpn-<версия>-android.apk` | открыть файл на телефоне, разрешить установку из этого источника |
| Ubuntu 22.04 / 24.04 | `tainavpn_<версия>_amd64.deb` | двойной клик или `sudo apt install ./tainavpn_<версия>_amd64.deb`; ярлык появится в меню приложений |

На Windows без прав администратора можно выбрать в настройках режим «Системный прокси» (только программы, которые его используют).
На Ubuntu пакет сам выдаёт программе право `CAP_NET_ADMIN`, поэтому режим «весь трафик» работает без sudo.
Android‑приложение само исключено из VPN, поэтому подписка обновляется напрямую, даже если прокси не работает.

### Языки

Интерфейс приложений — на русском и английском. По умолчанию выбирается язык системы, сменить можно в «Настройки → Язык».
Названия стран тоже показываются на выбранном языке. Все строки — в `ui/i18n.js`: чтобы добавить язык, добавьте ещё один блок с теми же ключами.

### iPhone и iPad

Версии для iOS нет: своё VPN‑приложение на iOS требует платного аккаунта Apple Developer ($99/год).

### Как выпустить новую версию

Поменяйте номер в файле **`VERSION`** (например, `1.0.0` → `1.0.1`) и сделайте push в `main`.
GitHub Actions соберёт приложения, проверит их и создаст релиз `v1.0.1` с тремя файлами.
Пока номер в `VERSION` не меняется, push только проверяет сборку, релиз не трогается.
Обновления ставятся поверх старой версии, настройки и прокси сохраняются.

**Подпись APK.** Сейчас APK подписывается ключом `android/app/tainavpn.jks` из репозитория (репозиторий приватный).
Чтобы перейти на ключ из секретов, добавьте `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` —
но учтите, что APK с другим ключом не установится поверх старого.

## Что делает конфиг sing-box на клиенте

* `tun` (весь трафик) или `mixed` + системный прокси (только десктоп);
* DNS — `1.1.1.1` по TCP через прокси (нет утечек DNS);
* локальная сеть — напрямую (переключатель в настройках);
* QUIC (UDP 443) блокируется, чтобы браузеры шли по TCP — через SOCKS5 так стабильнее;
* всё остальное — в SOCKS5.

Конфиг генерируется в `ui/app.js` (`buildConfig`), последний использованный сохраняется на десктопе в `%APPDATA%\Tainavpn\last-config.json` / `~/.config/Tainavpn/`.

## Разработка

* Go 1.25.5+, sing-box подключается как модуль `github.com/sagernet/sing-box v1.14.2`.
* Теги сборки ядра: `with_gvisor,badlinkname,tfogo_checklinkname0` и `-ldflags -checklinkname=0` (как в официальной сборке sing-box).
* Десктоп собирается обычным `go build -tags desktop,production ./desktop` (на Linux ещё `webkit2_41`).
* Android: `gomobile bind -target=android -javapkg com.tainavpn ./mobile -o android/app/libs/tainacore.aar`, затем `gradle -p android assembleRelease`.
* UI можно открыть в браузере (`ui/index.html`) — без нативной части он работает в режиме предпросмотра.

Лицензия sing-box — GPL‑3.0; так как он встроен в приложения, исходники этого проекта при распространении сборок тоже должны быть доступны под GPL‑3.0.
