# Tainavpn

Приложение для **Windows, Linux и Android**, которое отправляет весь трафик устройства в SOCKS5‑прокси.
Ядро — [sing-box](https://github.com/SagerNet/sing-box) 1.14 (встроен как библиотека).
Прокси можно получить со своего VPS одной кнопкой или вставить свой.

```
┌──────────── устройство ────────────┐            ┌──────────── VPS ─────────────┐
│ приложения → TUN → sing-box ──SOCKS5──────────▶ │ sing-box SOCKS5 :1080 → интернет│
│                 (Tainavpn)          │            │                               │
│   UI ── HTTPS /sub/<ключ> ─────────────────────▶ │ nginx → tainavpn-server :8090 │
└────────────────────────────────────┘            └───────────────────────────────┘
```

## Состав репозитория

| Папка | Что внутри |
|---|---|
| `server/` | `tainavpn-server`: встроенный sing-box (SOCKS5 с логином/паролем на каждого пользователя) + API для приложений + админ‑панель |
| `ui/` | общий интерфейс (HTML/JS) — один и тот же на десктопе и Android; здесь же генерируется конфиг sing-box |
| `core/` | обёртка над sing-box (запуск/остановка, логи) |
| `desktop/` | десктоп‑приложение на Wails (Windows/Linux) |
| `mobile/` | Go‑библиотека для Android (собирается `gomobile bind` в `.aar`), отдаёт sing-box TUN от VpnService |
| `android/` | Android‑приложение (Kotlin, VpnService + WebView с общим UI) |
| `deploy/` | Dockerfile, docker-compose, пример `.env` и конфиг nginx |

## Как приложение получает прокси с VPS

1. На VPS работает `tainavpn-server`. У каждого пользователя есть **ключ доступа** и свои логин/пароль SOCKS5.
2. Приложение по ссылке‑подписке `https://vpn.sdsds.top/sub/<ключ>` получает JSON с адресом, портом, логином и паролем.
   Перед каждым подключением подписка обновляется — если в админке сменить пароль или выключить ключ, это сразу подхватится.
3. Ключ можно получить двумя способами:
   * **кнопка «Получить прокси с сервера»** в приложении (`POST /api/v1/register`) — работает, если `TVPN_OPEN_REGISTRATION=true`; лимит — `TVPN_REGISTER_PER_DAY` ключей в сутки с одного IP;
   * **вручную в админ‑панели** (`https://vpn.sdsds.top/panel`) — «Создать ключ», ссылка копируется, её вставляют в приложении: «Добавить → С сервера → Добавить по ссылке».
4. В админ‑панели видно всех пользователей, последний вход и IP; ключ можно выключить, удалить или сменить ему пароль SOCKS.

Свой прокси добавляется во вкладке «Свой прокси»: ссылкой `socks5://логин:пароль@хост:порт`, строкой `хост:порт:логин:пароль` или полями.

## Сервер (VPS)

### Первый запуск через GitHub Actions

Вход под root не нужен: деплой заходит по SSH под обычным пользователем.

1. В **Settings → Secrets and variables → Actions** добавьте секреты:
   `VPS_HOST`, `VPS_PORT` (ваш SSH‑порт), `VPS_USER` (обычный пользователь), `VPS_SSH_KEY` (приватный ключ, публичный — в `~/.ssh/authorized_keys` этого пользователя).
2. Один раз на сервере дайте этому пользователю доступ к Docker: `sudo usermod -aG docker <пользователь>` и перезайдите.
   (Либо sudo без пароля для docker — деплой сам попробует `sudo -n docker`.)
3. **Actions → Deploy server → Run workflow** (в поле укажите домен, по умолчанию `vpn.sdsds.top`).
   Файлы ложатся в `~/tainavpn` пользователя деплоя — права root для этого не нужны
   (другую папку можно задать переменной репозитория `VPS_DIR`).
   При первом деплое создаётся `~/tainavpn/.env` со случайным `TVPN_ADMIN_TOKEN` — посмотреть: `grep ADMIN_TOKEN ~/tainavpn/.env`.
4. Nginx (существующие сайты не трогаются, тут один раз нужен sudo): скопируйте `deploy/nginx-vpn.conf` в `/etc/nginx/sites-available/vpn.sdsds.top`,
   включите (`ln -s … /etc/nginx/sites-enabled/`), `sudo nginx -t && sudo systemctl reload nginx`, затем `sudo certbot --nginx -d vpn.sdsds.top`.
   Не забудьте A‑запись `vpn.sdsds.top` → IP VPS.
5. Порт SOCKS5 `1080` (TCP и UDP) должен быть доступен снаружи. Фаервол не трогаем — если он выключен, ничего делать не нужно.

Дальше обновление сервера — той же кнопкой **Run workflow**.

### Переменные `.env`

См. `deploy/.env.example`: имя сервиса, публичный хост и порт SOCKS5, адрес API, токен и путь админки, саморегистрация.

### Безопасность

* SOCKS5 без пароля никогда не поднимается: если активных пользователей нет — порт не слушается.
* Клиенты не могут через прокси ходить в локальные/частные сети VPS (`127.0.0.1`, `10.0.0.0/8`, …) — это закрывает доступ к API и другим сервисам на сервере.
* SOCKS5 не шифрует трафик между устройством и VPS (HTTPS‑сайты при этом остаются зашифрованными). Если провайдер начнёт блокировать SOCKS5, следующим шагом можно добавить в тот же sing-box Shadowsocks/VLESS — архитектура это позволяет.

## Приложения

Сборки делает GitHub Actions (**Actions → Build**), файлы лежат в артефактах запуска.
Чтобы выпустить релиз со всеми файлами: `git tag v0.1.0 && git push --tags` — появится GitHub Release.

### Windows
`Tainavpn-windows-amd64.exe` — один файл, запускается с правами администратора (нужно для режима TUN).
Если нужен режим без прав — в настройках выберите «Системный прокси» (только программы, которые его используют).

### Linux
Архив `tainavpn-linux-amd64.tar.gz`, установка: `./install.sh` (кладёт в `~/.local/bin`, добавляет ярлык и выдаёт бинарнику `CAP_NET_ADMIN`, чтобы TUN работал без root).
Нужны `libgtk-3` и `libwebkit2gtk-4.1` (в Ubuntu 22.04+/Debian 12 есть).

### Android
`tainavpn-universal.apk` (или под конкретную архитектуру, обычно `arm64-v8a`). Android 7.0+.
Приложение само исключено из VPN, поэтому подписка обновляется напрямую, даже если прокси не работает.

**Подпись APK.** Сейчас APK подписывается ключом `android/app/tainavpn.jks` из репозитория (репозиторий приватный).
Чтобы перейти на ключ из секретов, добавьте `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` —
но учтите, что APK с другим ключом не установится поверх старого.

## Что делает конфиг sing-box на клиенте

* `tun` (весь трафик) или `mixed` + системный прокси (только десктоп);
* DNS — `1.1.1.1` по TCP через прокси (нет утечек DNS);
* локальная сеть — напрямую (переключатель в настройках);
* QUIC (UDP 443) блокируется, чтобы браузеры шли по TCP — через SOCKS5 так стабильнее;
* всё остальное — в SOCKS5.

Конфиг генерируется в `ui/app.js` (`buildConfig`), последний использованный сохраняется на десктопе в `%APPDATA%\Tainavpn\last-config.json` / `~/.config/Tainavpn/`.

## Разработка

* Go 1.25.5+, sing-box подключается как модуль `github.com/sagernet/sing-box v1.14.2`.
* Теги сборки ядра: `with_gvisor,badlinkname,tfogo_checklinkname0` и `-ldflags -checklinkname=0` (как в официальной сборке sing-box).
* Десктоп собирается обычным `go build -tags desktop,production ./desktop` (на Linux ещё `webkit2_41`).
* Android: `gomobile bind -target=android -javapkg com.tainavpn ./mobile -o android/app/libs/tainacore.aar`, затем `gradle -p android assembleRelease`.
* UI можно открыть в браузере (`ui/index.html`) — без нативной части он работает в режиме предпросмотра.
